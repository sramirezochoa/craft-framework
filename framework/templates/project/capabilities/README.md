# Capabilities

What the system does **today**. One file per capability, always current.

Amended at the end of every change that touches it (gate 6). If a capability
doc disagrees with the code, the doc is a bug.

See `framework/templates/capability.md` for the shape, and the working guide
for how to pick granularity.

Each document carries a status: `planned` (decided, not built), `active`,
`deprecated` or `superseded-by: <name>`. A new project starts with `planned`
documents, written by the `project-start` skill; a change turns each one
`active` when it is built.
